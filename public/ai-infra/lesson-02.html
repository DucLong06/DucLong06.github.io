2

Vì sao cầnWhy it matters

Người dùng gửi qua gateway một prompt RAG dài 8K token và phàn nàn: “đợi lâu mới có chữ đầu tiên, sau đó chữ ra rất nhanh”. Trên dashboard vLLM, time-to-first-token (TTFT) tăng vọt còn time-per-output-token (TPOT) gần như không đổi. Lý do nằm trong một lượt forward: với Qwen3-8B, prefill 8K token tốn 133.594 TFLOP, còn mỗi bước decode sau đó trên cùng context chỉ tốn 19.97 GFLOP (tính bởi course/m1/calc.py). Hiểu lượt forward là hiểu vì sao hai chỉ số này phản ứng khác nhau khi prompt dài ra.

A user sends an 8K-token RAG prompt through the gateway and complains: “the first word takes ages, then the rest streams quickly”. On the vLLM dashboard, time-to-first-token (TTFT) jumps while time-per-output-token (TPOT) barely moves. The reason is inside one forward pass: for Qwen3-8B, prefilling 8K tokens costs 133.594 TFLOP, while each later decode step on the same context costs only 19.97 GFLOP (computed by course/m1/calc.py). Understanding the forward pass explains why the two metrics react differently to longer prompts.

Hai loại việc trong một tầng

Two kinds of work per layer

“Attention handles information exchange between tokens, while the FFN performs a nonlinear transformation on each token's features independently.” (Bojie Li, Understanding AI Infra, Ch. 2)

Một tầng Qwen3-8B, lặp 36 lần (num_hidden_layers: 36):

“Attention handles information exchange between tokens, while the FFN performs a nonlinear transformation on each token's features independently.” (Bojie Li, Understanding AI Infra, Ch. 2)

One Qwen3-8B layer, repeated 36 times (num_hidden_layers: 36):

x - RMSNorm - q_proj / k_proj / v_proj - QK-Norm + RoPE - softmax(QK^T / sqrt(128) + mask) V
  - o_proj -(+x)- RMSNorm - SiLU(gate_proj) * up_proj - down_proj -(+)- next layer

Số liệu tính bởi course/m1/calc.py:

Computed by course/m1/calc.py:

  • Projection attention mỗi tầng N_proj = 41,943,040; FFN N_FFN = 3·d·f = 150,994,944. FFN chiếm 78.26% tham số projection, 288.00 MiB BF16 mỗi tầng.
  • Một nhân ma trận [m×k]·[k×n] tốn 2·m·k·n FLOPs. Vậy mỗi token qua projection + FFN của một tầng tốn F_linear = 2·(N_proj + N_FFN) = 385,875,968 FLOPs.
  • Attention giữa token: mỗi cặp query-key mỗi tầng tốn 4·n_Q·d_h = 16,384 FLOPs (QKᵀ và A·V, 32 query head). Số cặp nhân quả N_pair = B·(P·S + P(P+1)/2).
  • lm_head chỉ chạy cho token cuối: 2·d·V ≈ 1.24 GFLOP.
  • Attention projections per layer N_proj = 41,943,040; FFN N_FFN = 3·d·f = 150,994,944. The FFN is 78.26% of projection parameters, 288.00 MiB BF16 per layer.
  • A [m×k]·[k×n] matmul costs 2·m·k·n FLOPs, so each token through one layer's projections + FFN costs F_linear = 2·(N_proj + N_FFN) = 385,875,968 FLOPs.
  • Token-to-token attention: each query-key pair per layer costs 4·n_Q·d_h = 16,384 FLOPs (QKᵀ plus A·V over 32 query heads). Causal pairs N_pair = B·(P·S + P(P+1)/2).
  • lm_head runs only for the last token: 2·d·V ≈ 1.24 GFLOP.

Đọc bảng: prompt dài gấp đôi (2K lên 4K) thì phần linear gấp đôi, còn số cặp attention gấp x3.999 vì phần tam giác P(P+1)/2. Decode chỉ đưa 1 token mới qua projection; K, V của token cũ lấy từ cache (bài 03). Quy tắc nhanh “FLOPs/token ≈ 2N” cho 16.38 GFLOP: nó đếm cả bảng embedding (thực ra chỉ tra hàng) và bỏ qua attention, nên chỉ là ước lượng.

Reading the table: doubling the prompt (2K to 4K) doubles the linear part, but attention pairs grow x3.999 because of the P(P+1)/2 triangle. Decode pushes only 1 new token through the projections; old tokens' K and V come from the cache (lesson 03). The shortcut “FLOPs/token ≈ 2N” gives 16.38 GFLOP: it counts the embedding table (really a row lookup) and ignores attention, so treat it as an estimate.

Key notesKey notes

  1. Một tầng = attention (trao đổi giữa token) + FFN (biến đổi từng token), mỗi khối có RMSNorm và residual.
  2. Mọi projection là nhân ma trận: FLOPs = 2·m·k·n; weight không lớn lên khi số token m tăng, FLOPs thì có.
  3. Ở Qwen3-8B, FFN chiếm 78.26% tham số projection; đây là khối nặng nhất về bộ nhớ weight.
  4. Prefill: FLOPs linear tăng tuyến tính theo độ dài prompt, attention tăng gần bậc hai (2K lên 4K: x3.999 cặp).
  5. Decode: mỗi bước chỉ 1 token mới qua projection (19.97 GFLOP ở context 8K), nhưng vẫn phải đọc toàn bộ weight.
  6. Shape của k_proj nhỏ hơn q_proj (1024 so với 4096) là dấu hiệu model dùng GQA (bài 05).
  1. One layer = attention (exchange between tokens) + FFN (per-token transform), each wrapped in RMSNorm and a residual.
  2. Every projection is a matmul: FLOPs = 2·m·k·n; weights do not grow with the token count m, FLOPs do.
  3. In Qwen3-8B the FFN holds 78.26% of projection parameters, the heaviest block in weight memory.
  4. Prefill: linear FLOPs grow linearly with prompt length, attention almost quadratically (2K to 4K: x3.999 pairs).
  5. Decode: each step pushes only 1 new token through the projections (19.97 GFLOP at 8K context), but still reads every weight.
  6. k_proj being narrower than q_proj (1024 vs 4096) is the signature of GQA (lesson 05).

Tự kiểm traSelf-check

1. Nhìn shape k_proj [1024, 4096] và q_proj [4096, 4096] với head_dim 128, model có bao nhiêu query head và KV head?Given k_proj [1024, 4096], q_proj [4096, 4096] and head_dim 128, how many query and KV heads?

Lời giảiAnswer

4096/128 = 32 query head, 1024/128 = 8 KV head: 4 query head dùng chung một KV head (GQA).

4096/128 = 32 query heads, 1024/128 = 8 KV heads: 4 query heads share one KV head (GQA).

2. Prompt từ 2K lên 4K token. Phần linear và phần attention của prefill tăng bao nhiêu lần?The prompt grows from 2K to 4K tokens. How much do prefill's linear and attention parts grow?

Lời giảiAnswer

Linear từ 28,449.86 lên 56,899.73 GFLOP (gấp đôi). Attention từ 1,237.55 lên 4,949.01 GFLOP (số cặp x3.999), vì mỗi token mới phải chấm với mọi token đứng trước.

Linear 28,449.86 to 56,899.73 GFLOP (double). Attention 1,237.55 to 4,949.01 GFLOP (x3.999 pairs), because every new token scores against every earlier one.

3. Một bước decode ở context 8K tốn 19.97 GFLOP. Phần nào lớn nhất?One decode step at 8K context costs 19.97 GFLOP. Which part dominates?

Lời giảiAnswer

Linear 13.89 GFLOP (projection + FFN cho 1 token qua 36 tầng), sau đó attention 4.83 và lm_head 1.24.

Linear 13.89 GFLOP (projections + FFN for 1 token over 36 layers), then attention 4.83 and lm_head 1.24.

4. Vì sao TTFT tăng mạnh theo độ dài prompt còn TPOT gần như không?Why does TTFT rise sharply with prompt length while TPOT barely moves?

Lời giảiAnswer

TTFT chứa prefill, mà FLOPs prefill tăng theo P (linear) và gần P² (attention). TPOT là từng bước decode với m = 1 token, phần cố định (đọc weight, linear) không đổi; chỉ attention tăng chậm theo context.

TTFT contains prefill, whose FLOPs grow with P (linear) and nearly P² (attention). TPOT is one decode step with m = 1 token; its fixed part (weight reads, linear) does not change, only attention grows slowly with context.
